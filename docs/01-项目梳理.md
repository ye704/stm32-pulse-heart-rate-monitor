# 项目梳理 · 基于 STM32F411 的心率检测与波形显示数据采集系统

> 本文回答三个问题：**这个项目到底是什么**、**原始资料里有什么**、**哪些地方值得写进简历**。

---

## 一、项目定位

**一句话**：一套以 STM32F411RET6 为主控、以光电脉搏传感器（PPG）为信号源的便携式生理信号采集终端，
能够实时采集脉搏波形、解算心率并通过 TFT 屏本地显示、通过串口上传上位机。

**三句话版本**：

1. 信号链路：脉搏传感器输出与心搏同步的微弱模拟电压 → ADC 以 500 Hz 定频采样。
2. 算法链路：在 MCU 内做峰值/谷值跟踪 + 自适应阈值判定心搏，得到心搏间期（IBI）与心率（BPM）。
3. 输出链路：2.2″ SPI TFT 实时绘制波形与数值，同时通过 USART2 按自定义帧协议上传数据。

**项目来源**：电子设计竞赛作品，题目为"具波形显示功能的数据采集系统"，完成时间 2016.08。
原始资料中的"论文"文件是该题目的通用参考论文，并非本项目专属文档。

## 三、系统架构与数据流

```
                         ┌───────────────────────────────────────┐
   脉搏传感器             │            STM32F411RET6              │
   (PPG, 模拟输出)        │                                       │
      │                   │   ┌──────────────┐                    │
      │ OUT → PA0         │   │ TIM3  500 Hz │  2 ms 周期中断      │
      └──────────────────►│──►│  时基 + 计时  │                    │
                          │   └──────┬───────┘                    │
                          │          │ 触发 ADC1_IN0 单次转换       │
                          │          ▼                            │
                          │   ┌──────────────┐                    │
                          │   │ 采样值 Signal │                    │
                          │   └──────┬───────┘                    │
                          │          ▼                            │
                          │   ┌────────────────────┐              │
                          │   │ 心搏检测状态机       │              │
                          │   │ P/T 跟踪 + 自适应阈值│              │
                          │   │ IBI / BPM 滑动平均  │              │
                          │   └──────┬─────────────┘              │
                          │          │ QS 标志位                   │
                          └──────────┼───────────────────────────┘
                                     │ 主循环消费
                     ┌───────────────┴───────────────┐
                     ▼                               ▼
          ┌──────────────────┐            ┌────────────────────┐
          │ ILI9341 240×320  │            │ USART2 @115200     │
          │ 波形 + BPM + IBI │            │ 'S'/'B'/'Q' 帧协议  │
          └──────────────────┘            └────────────────────┘
```

**职责划分（这是一个值得在面试里讲的架构点）**：

- **中断上下文**：只做"实时性要求高、逻辑独立"的事 —— 采样、心搏检测、BPM 计算，通过 `QS` 标志位通知主循环。
- **主循环上下文**：做"慢操作" —— 波形绘制、数值刷新、串口发送。
- 二者通过共享变量（`Signal`、`BPM`、`IBI`、`QS`）通信，避免在中断里做 SPI 绘图和串口阻塞发送。

## 五、关键技术点（简历/面试素材）

### 1. 用"一个定时器"同时解决采样节拍和时间测量

心率计算依赖精确的**时间间隔**，波形显示依赖固定的**采样率**，这两件事天然冲突。
本项目用 TIM3 产生 2 ms 周期中断，一箭双雕：

- 每次中断触发一次 ADC 转换 → 等效 500 Hz 定频采样；
- 每次中断把 `sampleCounter` 加 2（单位为 ms）→ 得到与采样同源的毫秒时基。

由于计时与采样出自同一个时钟源，心搏间期的测量不存在累积误差，也不需要额外定时器。

> 公式：`16 MHz ÷ (PSC+1) ÷ (ARR+1) = 16 MHz ÷ 16 ÷ 2000 = 500 Hz` → 周期 2 ms。

### 2. 自适应阈值 —— 这个项目最有技术含量的一个点

脉搏波幅度会随按压力度、皮肤接触、血流状态大幅漂移。如果用固定阈值判定心搏，
轻按会漏检、重按会误检。项目采用**逐搏自适应**：

```
amp   = P - T            // 本次脉搏波的峰谷幅度
thresh = amp/2 + T       // 阈值取在峰谷中点
P = T = thresh           // 峰谷值复位，等待下一个波
```

即阈值不是常数，而是始终跟随上一拍的 50% 幅度。同时加了两个工程化保护：

- **二重脉抑制**：一次心搏后血管回弹会带来一个小波峰，因此在 `3/5 上搏间期` 内不重复触发；
- **失搏复位**：`2500 ms` 没有检测到心搏就把 P/T/thresh 全部复位到 512，避免信号丢失后阈值"卡死"。

### 3. 滑动平均抑制心率跳变

用最近 10 次 IBI 的算术平均计算 BPM：`BPM = 60000 / avg(IBI)`。
单次误触发不会让显示的心率剧烈跳动，代价是响应滞后约 10 拍 —— 这正是**"平滑度 vs 实时性"的取舍**，
是面试里很好的讨论点。

### 4. 不带硬件 SPI 外设、用 GPIO 手写时序

LCD 的 CS/SCK/SDI/DC/RESET 全部用普通 GPIO 模拟（PB0–PB5），
`LCD_Writ_Bus()` 通过"取最高位 → 移位 → 拉低拉高时钟"的方式逐位输出一个字节。
好处是引脚可任意分配、便于调试；代价是速度慢（这也直接限制了刷屏性能，见第六节）。

### 5. 对 ILI9341 的显存寻址理解

写像素前需要先用 `0x2A`/`0x2B` 设定列/行窗口，再用 `0x2C` 进入显存写入模式，
之后连续写入的数据会自动按窗口推进。项目用同一个 `Address_set()` 支撑了"画点""填充区域""画汉字"三类操作，
是理解 LCD 驱动本质的关键抽象。

### 6. 轻量自定义串口帧协议

```
 'S' | 123 | \r\n      ← 原始波形采样值
 'B' | 72  | \r\n      ← 心率 BPM
 'Q' | 833 | \r\n      ← 心搏间期 IBI (ms)
```

用单字符前缀区分数据类型，ASCII 数值 + CRLF 便于上位机按行解析，
配合 `printf` 重定向（`fputc` → `HAL_UART_Transmit`）实现零成本格式化输出。
这类"够用就好"的协议设计思路，在嵌入式岗位上是很常见的加分项。

### 7. 中断与主循环的职责边界

中断里只更新数据与标志位，耗时的绘图和串口发送全部放主循环。
虽然本项目没有用 RTOS，但这条原则与"ISR 要短"的工程共识一致，可直接作为架构能力佐证。

## 六、工程现状与缺口（重要 —— 决定了你该怎么写简历）

### 6.1 原工程**无法直接编译**（必须知道）

`main.c` 引用了 `stm32f4xx_hal.h`，Keil 工程的包含路径为 `..\Inc`、`..\Drivers\STM32F4xx_HAL_Driver\Inc`、
`..\Drivers\CMSIS\...`，但原始资料中**只提供了 `Src/` 目录下的 4 个文件**：

```
缺失的内容：
  Inc/                         stm32f4xx_hal_conf.h、stm32f4xx_it.h 等
  Drivers/STM32F4xx_HAL_Driver/
  Drivers/CMSIS/
  Src/system_stm32f4xx.c       系统时钟初始化
  Src/startup_stm32f411xe.s    启动文件（只剩编译出来的 .lst）
```

**结论**：这份源码是一份"应用层代码切片"，拿不到完整的 HAL/CMSIS 依赖。
如果要重新编译，需要**用 STM32CubeMX 针对 STM32F411RETx 新建工程，勾选 ADC1_IN0 / TIM3 / USART2 / GPIO，
再把 `main.c` 中的应用逻辑搬进去**。这一点必须在简历/面试中如实说明（"移植到 CubeMX 新工程"本身就是合理且有含量的说法）。

### 6.2 代码层面可优化点（面试讲"如果重做"用）

| 现状 | 问题 | 改进方向 |
| --- | --- | --- |
| ADC 单次转换在中断里同步读取 | CPU 在转换期间空等，且转换完成无中断 | ADC + DMA 循环模式 + 双缓冲，CPU 零参与 |
| 软件 SPI 逐位翻转 GPIO 刷屏 | 全屏清屏需写 240×320×2 = 150 KB，耗时数十至上百 ms | 改用硬件 SPI + DMA，或只刷新变化区域 |
| 每 60 点整屏 `LCD_Clear` 重绘 | 波形闪烁，且刷新周期被拉长 | 环形缓冲区 + 只重绘增量区域，或用双缓冲 |
| `delay_ms` 用空循环延时 | 无 `volatile`，开优化后可能被编译器优化掉 | 改用 `HAL_Delay` 或 `SysTick` 计时 |
| 采样值 `Signal` 跨中断/主循环共享 | 无原子保护，极端情况下读到撕裂值 | 临界区保护或改用单字读写的缓冲队列 |
| 未做 ADC 校准与中值滤波 | 零点漂移影响基线判断 | `HAL_ADCEx_Calibration_Start` + 上电基线自校准 |
| 心率无合理区间校验 | 异常值（如 20 BPM 或 250 BPM）直接显示 | 增加 40–180 BPM 有效区间与置信度判定 |
| UI 标注 "HRV" 实际显示 IBI | 概念不严谨（HRV 需 RR 间期序列的统计指标） | 改标 IBI，或真正计算 SDNN/RMSSD |
| 未使用 RTOS / 低功耗 | 主循环 `HAL_Delay(20)` 空转，功耗高 | 事件驱动 + STOP 模式，适合可穿戴场景 |

### 6.3 代码风格观察

- 注释以中文为主，部分位置因编码不一致显示为乱码（GBK 与 UTF-8 混用），仓库保留原样未做批量修改；
- 单文件 26 KB 的 `main.c` 承载了 LCD 驱动、字库渲染、算法与业务逻辑 —— 属于"能跑但难维护"的典型竞赛代码，
  这一点也可以作为"如果重构，我会按驱动层/算法层/应用层拆分"的话题。
