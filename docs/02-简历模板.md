## 3. 版本 C · 详版（推荐，标准项目经历块）

**项目名称**：基于 STM32F411 的心率检测与波形显示数据采集系统
**项目角色**：嵌入式软件与硬件设计（<按实际填写：独立完成 / 负责固件与 PCB / 负责算法与显示>）
**项目时间**：2016.08 – 2016.09
**技术栈**：STM32F411RET6 · 嵌入式 C (C99) · Keil MDK-ARM 5 · STM32CubeMX / STM32 HAL · ADC · 定时器中断 · ILI9341 · 软件 SPI · UART · Altium Designer

**项目背景**

针对便携式生理信号采集场景，以竞赛指定 Pulse Sensor 光电脉搏传感器为信号源，设计并实现一套集"采集—解算—显示—上传"于一体的嵌入式系统：以固定采样率采集 PPG 模拟信号，在 MCU 端完成心搏检测与心率解算，并在本地 TFT 上实时可视化波形与数值，同时将数据推送至上位机。

**主要工作**

1. **采集架构设计（ADC + 定时器中断）**
   采用 TIM3 溢出中断构建 2 ms 周期时基，将系统时钟 HSI 16 MHz 经 16 分频后计满 2000 计数得到 500 Hz 中断，在中断服务函数中触发 ADC1_IN0（PA0）单次转换并读取结果；
   复用同一时基累加得到毫秒级计时变量，为心搏间期测量提供统一时间基准，避免了额外定时器与阻塞式延时的引入。

2. **心率检测算法实现与调优**
   移植并适配开源 PulseSensor 峰值检测算法到 STM32 HAL 平台：以峰值 P、谷值 T 动态跟踪脉搏波包络，
   按 `thresh = amp/2 + T` 逐搏更新自适应触发阈值，并加入二重脉（dichrotic）抑制窗口（3/5 上搏间期）与 2500 ms 失搏复位机制，
   提升手臂抖动与接触不良场景下的检测稳定性；采用最近 10 次心搏间期的滑动平均计算 BPM，抑制单次误检导致的心率跳变。

3. **显示驱动与图形界面开发**
   依据 ILI9341 数据手册手写初始化寄存器序列、GRAM 行列寻址（0x2A/0x2B/0x2C）与 RGB565 色深配置，
   在 PB0–PB5 上以软件 SPI（片选/时钟/数据/命令/复位）实现点、线、矩形、填充、圆等图元；
   构建中英文字库显示层（16×16 与 32×32 汉字点阵、16×8 ASCII），实现标题、标签与实时数值的混合排版。

4. **波形可视化与刷新策略**
   在 240 像素宽的屏上以 60 点为一屏对脉搏波形进行差分线段绘制，每采满 60 点局部清屏重绘，
   兼顾刷新速率与 SPI 带宽占用，使波形滚动流畅且数值与波形同步更新。

5. **数据通信协议设计**
   自定义轻量帧协议：以 `'S'` / `'B'` / `'Q'` 单字符前缀标识原始波形、心率、心搏间期三类数据，
   后接 ASCII 数值并以 CRLF 结尾，便于上位机按行解析；通过重定向 `printf` 到 USART2 实现格式化输出，
   在 115200 bps 下稳定上传数据。

6. **硬件设计与联调**
   使用 Altium Designer 完成核心板承载底板原理图与 PCB 设计，包含双列 20 Pin 核心板插座、
   TFT 模组与脉搏传感器模组接口、电源指示电路，并完成打样后的软硬件联调（信号偏置校准、阈值参数整定、显示时序调试）。

7. **测试与验证**
   【按实际填写，例如：以 <参考设备/手工计数法> 为基准，在 <静息/运动后> 状态下对比测试，心率测量误差约 ±<N> BPM；
   连续运行 <N> 分钟无失步、无死机】。

**项目成果**

- 实现 <40–180> BPM 范围内的脉搏波形实时采集与心率解算，心率显示误差 <±N> BPM（对比 <参考方式>）。
- 波形以 <N> 点/秒刷新，TFT 上波形、心率与心搏间期同步显示，同时通过串口向上位机输出数据流。
- 完成从原理图设计、PCB 打样到固件开发与整机联调的完整闭环，交付 <原理图/PCB/程序源码/设计说明> 全套资料。

**项目收获**

- 掌握 MCU 中断驱动的定频采样架构与中断/主循环职责划分（ISR 只做采集与解算，显示与通信放在主循环）。
- 掌握时域生理信号的特征提取思路，理解自适应阈值相对固定阈值的鲁棒性优势。
- 具备从时序图/寄存器手册出发手写外设驱动的能力，以及串口协议设计与上位机联调经验。

**🔗 项目链接**：https://github.com/ye704/stm32-pulse-heart-rate-monitor

## 4. 版本 D · STAR 口述版（面试自我介绍用，约 90 秒）

> 面试官问"挑一个你印象最深的项目讲讲"，照这个顺序说，不要背简历原文。

**S（背景）**：这是一个电子设计竞赛项目，要做一套带波形显示的生理信号采集系统。
信号源是光电脉搏传感器，输出的是随心跳起伏的模拟电压，我需要把它变成屏幕上的波形和一个心率数字。

**T（任务）**：难点有三个 —— 一是采样必须等间隔，否则算出来的心率不准；二是脉搏波幅度会随按压力度、皮肤接触漂移，固定阈值一定会误判；三是 MCU 上没有现成的屏幕驱动，要自己写。

**A（行动）**：我用定时器中断建了 2 ms 的时基，在中断里触发 ADC 采样，同时拿这个时基当毫秒计数器，这样心搏间期的测量和采样时间基准是统一的。
算法上我用了峰值-谷值跟踪，阈值取自适应的一半幅度，另外加了一个"三倍上搏间期内不重复触发"的窗口来滤掉二重脉。
显示部分我对着 ILI9341 手册写初始化序列和显存寻址，用软件 SPI 先把点、线、字库跑通，再做波形刷新。
上位机那边定了一个简单协议，单字符前缀区分数据类型，后面跟数值和换行，方便解析。

**R（结果）**：最终实现了 40–180 BPM 范围内的波形采集与心率显示，误差在 ±<N> BPM 以内，
并从原理图、PCB 到固件完整做了一遍。现在回头看，如果重做，我会把 ADC 换成 DMA + 双缓冲，把显示搬到 SPI+DMA 上，进一步降低主循环的阻塞。

**🔗 项目链接**：https://github.com/ye704/stm32-pulse-heart-rate-monitor

## 7. 常见扣分点

| 坑 | 后果 | 正确做法 |
| --- | --- | --- |
| 把开源算法写成"我设计了算法" | 被追问算法推导时当场露馅 | 写"移植并适配/参数整定"，能讲清原理即可加分 |
| 写"精度达医疗级" | 明显夸大，面试官会直接质疑 | 写实测误差范围与对比基准 |
| 只写技术名词，不写做了什么 | HR 看不懂，技术面试也抓不到重点 | 每条都包含"用什么方法 → 解决了什么问题" |
